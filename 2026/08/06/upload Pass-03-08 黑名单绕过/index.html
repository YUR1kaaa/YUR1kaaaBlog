文件上传漏洞

文件上传漏洞是指服务器未充分校验用户上传文件的类型、内容或大小，导致攻击者可上传恶意脚本（如Webshell）并远程执行，从而控制服务器。

文件上传绕过检测：

  • 操作系统漏洞
  • Apache解析漏洞
  • 图片木马

靶场：upload-labs

Pass-03

校验代码：

trim() ：去除字符串首尾空格、换行符、制表符等空白字符；

deldot() ：这不是 PHP 内置函数，是自定义函数。从注释看，作用是删除文件名末尾的点；

strrchr() ：从字符串中查找最后一次出现的 **.**，并返回从该位置到字符串结尾的部分（包含点）；

**strtolower()**：替换为小写；

in_array() ：检查值是否在数组中

​ $_FILES 这是PHP自动创建的数组，存放所有上传文件的信息；

​ ['upload_file'] 指的是HTML表单中 <input type="file" name="upload_file"> 这个文件框；

​ ['tmp_name'] 文件上传后，PHP会先把文件存在临时文件夹，这个值就是临时文件路径；

​ 这一行代码获取的是临时文件名称

date("YmdHis") 生成时间戳；

move_uploaded_file(start, end) 把文件从 start 位置（路径）移动到 end，这个函数返回 true （成功）或 false （失败）;

Pass-05

增加 .htaccess 黑名单拦截；

检查源码，发现前面两Pass校验文件名用到 strtolower() 这个函数，这两问的弱点是黑名单不完整，通过传php其它非标准扩展名和配置类文件绕过，

而本Pass完善了黑名单拦截却去掉了大小写检查

本靶场环境中 Windows+Apache 系统对大小写不敏感，因此将 .php 改为大写可以绕过黑名单，且继续被服务器解析为 .php

补充：大小写不敏感系统

Pass-06

补全大小写检查，但去掉了 trim() 空白字符校验

Windows 文件系统写入时会自动剥掉尾随空格或点，于是黑名单对比绕过（有空格）,实际解析为 .php （无空格）

可以在文件后缀名 .php 后加空格，对比后缀名时不匹配，但windows文件系统上传时会自动忽略空白字符

补充：正是由于windows系统限制，无法创建这样的空白后缀文件，只能通过抓包改名或写脚本

Pass-07

本Pass的黑名单已经补全（PHP、ASP、JSP 各种大小写变体、.htaccess 等），无法再用非标准后缀或配置文件绕过。

但对比 Pass-03 的源码可以发现，本Pass删掉了 deldot() （删除文件名末尾点的自定义函数）

故上传 shell.php.（文件名末尾加点）

  1. strrchr('shell.php.', '.') 返回 .，即扩展名被判定为 .，不在黑名单中 → 校验通过；
  2. 保存时用的是原始文件名 $img_path = UPLOAD_PATH.'/'.$file_name，即 shell.php.；
  3. 但 Windows 文件系统写入时会自动剥掉文件名末尾的点（和空格），实际落盘为 shell.php；
  4. Apache 将 shell.php 解析为 PHP 执行 → 绕过成功。

由于 Windows 文件系统限制，无法在本地直接创建 shell.php. 这样的文件名，需要通过抓包修改文件名（filename="shell.php."）或脚本上传

Pass-08

本Pass又补足了 deldot() ，但去掉了 ::$DATA ；

利用的是 ntfs 文件系统过滤机制，::$data 是 ntfs 的流语法，把这个文件名当作 NTFS 文件的默认流路径来解析，最后只留下 .php ，而黑名单拦截时不会过滤流名，依然能绕过

由于 ntfs 是Windows文件系统限制，依然只能抓包或写脚本上传；
