文件上传漏洞

文件上传漏洞是指服务器未充分校验用户上传文件的类型、内容或大小，导致攻击者可上传恶意脚本（如Webshell）并远程执行，从而控制服务器。

Pass-11&12

GET/POST 0x00截断

00 截断是操作系统层的漏洞。

由于操作系统是C语言或汇编语言编写的，这两种语言在定义字符串时，都是以 **\0**（0x00）作为字符串的结尾；

操作系统在识别字符串时，当读取到 \0 字符时，就认为读取到了一个字符串的结束符号；

因此，我们可以通过修改数据包，插入 \0 字符的方式，达到字符串截断的目的

本题做了白名单校验后缀

**strrpos(string, find, start)**：查找子串在字符串中最后一次出现的位置, 返回从 start 开始的下标；

默认 start 为 0 ，找不到函数返回 false ；

提取上传的文件名中最后一次出现点的位置，从该位置截取到文件名最后（只识别最后一个后缀名）；

move_uploaded_file 函数把合格文件落盘到 $img_path 这个目标路径，

但该路径的前半部分直接取用户上传路径，因此这个目标路径是用户可控的

本题上传表单中：

action 在默认url外额外指定了一个get参数 ?save_path=../upload/

$img_path 正是接受了这个参数中的 save_path

在合适位置插入一个 %00 ，就可以截断后面的所有不可控内容。

在后缀校验时，提取的是文件的 filename 这个属性；

而最终 move_uploaded_file 接收的部分重点在 save_path 这个部分，是由get请求上传的；

如果直接改一个 shell.php%00 ，第一关后缀校验就从点号开始被全拦下了

因此上传合法后缀图片但伪装木马，抓包让 filename 合法，get请求行里加 shell.php%00

上传后报错正常，提示服务器中找不到这个文件，这是肯定的，因为这个路径是我们有目的地拼凑的

而乱码是因为网页渲染 \0 错误，实际上绕过已经成功

我们现在把shell交给服务器解析，删掉后面不需要的部分

绕过成功
