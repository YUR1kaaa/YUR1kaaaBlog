Pass 17

源代码：

move_uploaded_file() 将上传的临时文件移动到目标路径；

substr($file_name, strrpos($file_name, ".")+1) 提取最后一个 . 之后的扩展名；

rename() 用于重命名文件或目录，也可以将文件移动到同一个文件系统中的不同路径；

unlink() 用于删除一个文件。

逻辑分析

代码的执行顺序是：

漏洞点：先落盘，后校验，再删除。

无论后缀是否合法，文件都会先被 move_uploaded_file() 写到 ../upload/ 目录下。如果后缀不在白名单（jpg|png|gif）里，才会 unlink() 删除。

从 move_uploaded_file() 到 unlink() 之间存在一个时间窗口：在这个窗口内，文件真实存在于服务器上，且可以被 Apache 解析执行。

[!IMPORTANT]

条件竞争（Race Condition）

条件竞争漏洞的核心是：程序的正确性依赖于事件发生的顺序，而攻击者可以操控这个顺序。

本 Pass 中，代码假设「校验 → 删除」是原子操作，但实际上：

  1. 文件落盘（可被访问）
  2. 校验后缀（有时间差）
  3. 删除文件

如果在步骤 2 的间隙，攻击者并发请求该文件，就能在删除前执行 PHP 代码。

利用思路

上传一个 shell.php，同时不断并发请求 /upload/shell.php，抢在 unlink() 删除之前执行 PHP 代码。

由于文件会被立即删除，payload 需要在被执行的瞬间生成一个持久 webshell：

dirname(__FILE__) 获取当前文件所在目录的绝对路径，确保 pass17.php 写入 /upload/ 目录。

Burp 配置 intruder：

① 上传线程（POST）

Sniper、空payloads、并发数20

② 访问线程（GET）

Sniper、空payloads、并发数100（远大于POST，增加竞争机会）

[!TIP]

GET 并发数要远大于 POST 并发数。

每个文件落地瞬间只有极短的生命周期，很多 GET 线程同时去抢，才能保证至少有一个请求在 PHP 读取文件之前完成执行。

竞争成功

观察 GET Intruder 的返回结果：

  • 404 → 文件已被删除，竞争未命中
  • 200 + PHP 报错 → 文件存在但 PHP 读取时被删，接近成功
  • 200 + Content-Length: 0 → 竞争成功，shell.php 被执行

竞争成功后，持久化 payload 已经生成 pass17.php。访问：
